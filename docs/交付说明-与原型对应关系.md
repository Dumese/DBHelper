## 一、先说明三件与原型/文档不一致的事实

这三点不是遗漏，而是**在「真实逻辑」与「像素复刻」冲突时的取舍**，请先确认是否接受：

| # | 现象 | 原因 | 当前处理 |
|---|---|---|---|
| 1 | 首屏连接清单里 `production / staging / cache / analytics / logs` 保留原型端点，但**首次启动连不上** | 原型假设这些服务端真实存在；本机无 MySQL/PG/Redis/Mongo/ES 实例（且按要求不使用 Docker） | 保留配置（端点、类型、分组、颜色与原型一致）；另建 3 条本地 SQLite 连接 `local / sandbox / scratch`，开箱即可查询、浏览对象、画 ER 图、看监控 |
| 2 | 查询/数据/ER/监控四屏的面包屑第一段是 `local` 而非 `production` | 同上：`production` 是 MySQL，无服务端 | 结构与层级完全一致（连接 / 库 / 表 / 视图），仅连接名不同；接上真实 MySQL 后即为 `production` |
| 3 | 原型中 `gmv decimal(10,2)` 显示 `12,480.00`，SQLite 动态类型只回传 REAL | SQLite 不保留 DECIMAL 声明精度 | 驱动层回填声明类型（`describe_table` → 结果列类型），UI 按 scale 补零，仍显示 `12,480.00` |

另外两处**必须提前说明的部署前置条件**：

- **Oracle**：`rust-oracle` 经 ODPI-C 调用 OCI。编译不需要客户端，**运行需要 Oracle Instant Client**（23ai 起可用 thin 模式）。未安装时连接会返回明确错误而不是崩溃。
- **Elasticsearch**：官方 `elasticsearch` crate 与服务端版本耦合过紧，按规格书 §四 允许的兜底方案改用 `reqwest + serde_json` 直连 REST，DSL 能力完整。

## 三、逐项对照：需求文档硬性条款

| 条款 | 状态 | 证据 |
|---|---|---|
| 8 种数据库驱动全部内置，不可 feature 裁剪 | ✅ 代码完整 | `crates/drivers/{driver-*}` 九个 crate 全部在 workspace 中无条件编译 |
| 统一 `Driver` trait + 枚举分派 | ✅ | `rel_common::RelationalDriver`、`core::registry::Handle` |
| 所有 I/O 走 tokio，结果流式回传 | ✅ | `AppCore::run_query` + 有界通道（8×200 行） |
| 结果集上限 / 执行超时 | ✅ | `max_rows`（默认 1000）、`statement_timeout`（默认 30s） |
| 单连接并发 ≤4 | ✅ | `registry::MAX_CONCURRENT_QUERIES` + `Semaphore` |
| 内存有界与告警 | ✅ | `sysinfo` 每秒采样，超阈值写入 `metrics.alert` |
| 凭据 AES-256-GCM + 主密钥入 Credential Manager/DPAPI | ✅ | `utils/vault.rs` |
| 高危语句二次确认 + 影响行数预估 | ✅ | `sql::danger_of` + `estimate_affected` + 确认弹层 |
| 只读连接禁止写 | ✅ | `AppCore::run_query` 在执行前拦截 |
| 参数化写入 | ✅（SQLite）/ ⚠️（其余） | `RowWriter` 用 `QueryBuilder::push_bind`；MySQL/PG 的行内提交尚未接入，UI 会明确提示 |
| 数据网格虚拟滚动 | ⚠️ 分页 + 有界渲染 | 每页 100 行、仅渲染当前页；未做逐行窗口化 |
| 亮/暗主题、多语言、快捷键 | ⚠️ 部分 | 主题 ✅；语言切换已持久化但文案未全量翻译；快捷键支持 F5/Ctrl+Enter/Ctrl+S/Ctrl+C/V/X/A |
| 安装包 | ✅ | `installer`（setup.exe 内嵌主程序 + 快捷方式 + 卸载项） |

## 四、本轮实机验证（2026-10-20，debug 构建 + 150% DPI）

在 Windows 实机上逐屏点击验证，截图见 `docs/screenshots/`。过程中修复了以下**真实缺陷**
（均为「编译通过但运行结果不对」的类型）：

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 查询结果里 `COUNT(...)`、`SUM(...)` 等聚合列全显示 `NULL` | SQLite 驱动按 `row.column(i).type_info()`（语句声明类型）判断，聚合列声明类型为 NULL，提前返回 `Null` | 改用 `try_get_raw(i).type_info()`（`sqlite3_value_type` 运行时类型）；列头类型也按首行实际值修正 |
| 2 | 首屏查询一直停在「执行中…」 | 启动首帧渲染（debug + 大面积 SVG）耗时数秒，事件排队；非死锁 | 无需改代码；release 构建首帧明显更快，已用日志确认事件随后正常到达 |
| 3 | 结果网格最后一列被窗口裁掉 | 列宽用 `FillPortion`，单元格文本不换行会把列撑开，总宽超出面板 | 改为 `Responsive` 取可用宽度 → 计算像素列宽 + 单元格 `clip(true)`；查询页与数据页同时修复 |
| 4 | 数据网格只有斑马纹、没有表头与内容 | `Msg::DataLoaded` 只存了 `def`，从未写入 `tab.columns` | 由表结构反射填充 `columns`（`ColumnDef` → `ColumnMeta`） |
| 5 | ER 图没有外键连线，表卡片也没有 FK 标记 | `PRAGMA foreign_key_list` 六元组按 (id, seq, table, from, to, …) 解析，代码却把第 3 项当成本表列名 | 按正确列序取「本表列 / 引用表 / 引用列」 |
| 6 | ER 图第三列卡片超出画布 | 布局固定 3 列 × 300px 间距（40+600+240 > 画布宽） | 间距改 280、起点 40，三列总宽 840 可容于 870 画布 |
| 7 | 连接页与弹层出现灰色半透明方块盖住内容 | iced tiny-skia 后端对大半径 `Shadow` 绘制异常（阴影盖在内容之上） | 移除向导卡片与弹层的阴影，改用描边 + 遮罩表达层级 |
| 8 | 最近连接里的 SQLite 路径把右侧面板撑出窗口 | 端点文案重复拼接类型且带完整路径 | 新增 `endpoint_short()`（文件库只显示文件名），并对副标题做定宽裁剪 |
| 9 | 设置页左侧导航点了没反应 | 视图把三张配置卡一次性铺开，导航只改变高亮 | 按 `settings_ui.section` 只渲染当前分区 |
| 10 | 没有进入设置页的入口 | `Msg::OpenSettings` 存在但没有任何 UI 触发 | 侧栏页脚整体可点 + 齿轮按钮进入设置；页脚文案精简为「Vault 已加密」 |
| 11 | 侧栏页脚两个图标按钮点不动 | 页脚行内按钮的命中区与实际绘制位置不一致 | 页脚外层改用 `mouse_area`（以容器矩形为热区），分段控件同样改为 `mouse_area` |

> 说明：第 11 条的根因尚未追到 iced 内部（同一页面里其它 button 正常），
> 采用 `mouse_area` 规避后行为稳定；分段控件（浅色/深色、无衬线/衬线、导出格式）已逐一实测可切换。

## 五、第二轮对齐原型的调整（2026-10-21）

针对「未严格 1:1、错位多、下拉直角」的反馈，按原型（1440×900，逐像素量取）重做外壳与组件：

| 项 | 原型实测（设计 px） | 调整后 |
|---|---|---|
| 窗口 | 1440×900 | 1440×900（原 1080×680，导致所有比例偏大） |
| 标题栏 / 面包屑 / 页签 / 状态栏 | 32 / 41 / 36 / 24 | 32 / 40 / 36 / 24，内容垂直居中 |
| 侧栏 / 最近连接面板 | 240 / 369 | 240 / 360 |
| 页签样式 | 左侧灰底胶囊、无图标 | 同上（原为白底描边 + 图标） |
| 结果页签 | 纯文本，选中加粗 | 同上（原为描边胶囊） |
| 表格表头 | 列名深色 + 类型小写浅灰，仅度量列右对齐 | 同上（原为大写类型、按类型右对齐） |
| 新建连接卡片 | 步骤文案在标题下一行 | 同上（原与标题同行右对齐） |
| 下拉框 | 白底 1px 描边、6px 圆角 | 关闭态与展开层均 6px 圆角（原为直角灰块） |

同时修复与新增：

- 字体统一为 **Noto Sans SC / Noto Serif SC / JetBrains Mono**，旧配置启动时自动迁移；
- 侧栏默认展开「库 → 表」，与原型首屏一致；「视图」分组不再误收索引；
- 无边框窗口的**最大化/F11/边缘拖拽缩放**：`toggle_maximize` 对 `decorations(false)` 无效，
  改为 Win32 `ShowWindow`，缩放用光标位置 + 窗口矩形自行计算；
- 编辑器与结果区改为 2:3 比例，最大化时自动铺满；表格列宽用 `Responsive` 计算。

## 六、验证方式

1. `cargo test -p dbhelper-utils -p driver-sqlite`：SQL 词法/危险语句/格式化 + SQLite 端到端。
2. `cargo test --test drivers_smoke -- --ignored`：其余 7 种数据库（需自备服务端与对应环境变量）。
3. 实机运行 `target/release/dbhelper.exe`，逐屏截图与原型比对（见 `docs/screenshots/`，
   含 p01 连接管理、p02 查询编辑器、p03 数据网格、p04 ER、p08 监控、p10 设置、导出向导）。
4. 安装包：`target/release/dbhelper-setup.exe` 安装到 `%LOCALAPPDATA%\DBHelper`，验证开始菜单项、桌面快捷方式与卸载项。
